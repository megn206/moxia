# 墨匣 · Moxia

> 把灵感养成故事的小说创作工作台 —— 灵感卡片 · 写作台 · 剧情脉络，三模式一体联动。

墨匣是一款纯前端、单文件的小说创作工具：灵感卡片帮你随手捕捉脑洞，写作台让章节落笔成书，剧情脉络把人物与伏笔织成故事网。所有数据保存在本地浏览器，支持云端同步与灵感广场分享。

- **在线版**：<https://megn206.github.io/moxia/>
- **源码仓库**：<https://github.com/megn206/moxia>

---

## 快速开始

1. 打开在线版（推荐，可直连云同步）或本地双击 `index.html`；
2. 在**灵感模式**随手新建卡片，记录任何脑洞；
3. 切到**写作模式**创建作品与章节，正文自动保存；
4. 切到**脉络模式**把卡片连成剧情网，把章节放进时间轴；
5. 需要多设备同步时，打开「云阁」配置云端（Supabase / CloudBase 双后端可选），或两台设备连同一 Wi-Fi 用「局域网直连」点对点互传。

> 本地 `file://` 打开时，浏览器安全策略会阻止直连云端；要用云同步请打开在线版。

## 三大模式

墨匣的三个模式平级共存、数据互相独立，但可以通过引用与拖拽互相借用。

### 🧠 灵感模式
- 卡片式灵感收集：文本、图片、分类、便签、时间轴
- 卡片类型：**灵感卡 / 人物卡 / 伏笔卡**（人物卡、伏笔卡有专属编辑界面与展示样式）
- 分类可增删改（改名称会同步到已有卡片），颜色与形状自定义
- 卡片排序：默认 / 随机 / 高亮回顾；搜索高亮命中
- **相似查重**：一键找出相似度 ≥50% 的重复卡片，相似度阈值可调（30%–90%），可逐对忽略或删除（删除走回收站）
- 关键词联想、灵感接龙（AI 助手栏）
- 卡片引用他人灵感（拖卡到写作/脉络切换按钮即可插入）

### ✍️ 写作模式（写作台）
- 书册树：作品 → 卷 → 章节，三级结构
- 正文编辑器：自动保存、字数/目标统计、专注模式、阅读预览、导出 TXT
- 右侧写作助手：相关灵感、人物/伏笔速查、素材库
- 新章节 / 新卷快捷按钮；章节卡片可拖入脉络时间轴

### 🕸 脉络模式
- 画布节点：灵感卡片、人物卡、伏笔卡、写作章节节点（橙色）全部可入画
- 连线类型：关联 / 伏笔 / 人物关系 / 人物出场 / 对照 / 配角
- 长按拖动连线，点击节点查看详情；横向时间轴模式整理剧情
- 节点显示标题前 3 字，无标题显示内容前 3 字

## 跨模式联动（本次新增）

写作台与灵感、脉络全面打通：

| 功能 | 入口 | 说明 |
|---|---|---|
| 📇 素材库 | 写作台功能区 | 本册全部灵感/人物/伏笔卡，点击插入 `[@卡名]` 引用 |
| 🎯 大纲转章 | 写作台功能区 | 把情节/大纲/世界观卡一键生成章节并挂接素材 |
| 👥 人物出场 | 写作台功能区 | 统计当前章节提到的人物卡次数，可插入引用 |
| 🔍 全局搜索 | 写作台功能区 | 同时搜章节正文、灵感、人物、伏笔，章节一键跳转、卡片插入引用 |
| 拖卡入章 | 从灵感区拖卡到写作台 | 拖入编辑器自动插入引用标记并记入素材 |
| 伏笔回写 | 自动 | 正文写 `【伏笔：xxx】`，自动记入对应伏笔卡 |
| 章节节点 | 脉络模式 | 写作台章节自动出现在脉络画布，可连边、可拖入时间轴 |

正文中 `[@id:名字]` 形式的引用，在编辑时会直接渲染为可悬停的《名字》引用小卡（悬停或点击即可查看对应灵感卡的分类、标签与内容），保存后自动还原为存储标记，阅读预览同样渲染为小卡。

## 云阁 · 云同步

云端同步采用**双后端并存、随时切换**：

- **腾讯云开发 CloudBase（国内直连，推荐）**：环境 ID + Publishable Key（可留空），国内线路更稳；免费体验版 3000 资源点/月，需开匿名登录、配置 Web 安全域名、建集合 `idea_cards`
- **Supabase（海外直连）**：项目 URL + anon key 配置，旧配置自动迁移
- 切换后端不影响本机数据，两套后端同步格式完全一致

功能要点：

- 端到端加密：数据用你的口令加密后上传，服务端只见密文
- 同步内容：灵感卡、分类设置、写作台书册（作品/卷/章节/正文）
- 云备份：云端快照与导出/导入备份均完整包含写作台书册，可一键恢复
- 冲突处理：按更新时间合并（自动校正设备时钟偏差），删除有墓碑标记；本地与云端同时修改的卡会存入「冲突备份」面板，可一键用云端版替换或忽略
- 删除记录清理：90 天前过期删除记录可在用量面板一键清理（CloudBase 直接删 / Supabase 生成 SQL）
- **局域网直连**：两台设备连同一 Wi-Fi（手机热点也行），点对点免服务器互传快照（合并卡片与设置），没网也能用
- 自动暂停：无更新内容时自动停止同步，不空转
- 配置方式：打开「云阁」→ 选后端类型 → 填对应配置 → 房间名 / 口令

## 更新日志

- **v132 卷名跨端同步 + 修掉同步脏标记被持久化的隐患（按上轮三条取舍里选定的第 3 条）**：①**补“重命名卷”入口**：写作台卷头新增 ✎ 按钮（`renameVol`），改名时给卷自身写 `updatedAt` 并刷新书级 `WB._updatedAt`，`newVol` 新建卷同样带 `updatedAt`；此前卷名只能在新建时输入，建完就改不了。②**`__wbMerge` 同步卷名**：同名卷只在“远端卷 `updatedAt` 更晚”时覆盖，双方都是老数据（无卷时间戳）一律不覆盖；此前合并只补缺失卷、从不更新卷名，一台改了卷名另一台永远看不到。之所以不用书级 `_updatedAt` 判断，是因为它只在整本应用/合并时赋值、平时恒为 0，用它等于“远端有名字就覆盖”，会把刚改好的名字盖回旧名。③**排查中发现并修掉一个更严重的隐患**：`__wbApply` 里置 `WB._applying=true` 后立刻 `wbSave()`，而 `wbSave` 序列化的是整个 `WB` 对象，于是 `_applying:true` 被写进 localStorage；下次加载后该标记常驻为真，`wbSave` 里 `if (ok && !WB._applying && __wbMarkDirty)` 永不成立，书稿改动不再标脏，云端/局域网增量同步收不到更新（表现为“本机明明一直在写，另一台始终拉不到新稿”）。修法：`wbSave` 序列化时跳过 `_applying`，`wbLoad` 顺带清掉历史数据里可能已存在的脏标记。复测（独立 profile + Edge 无头 CDP）：`__wbApply` 后存储串不含 `_applying`、内存中也已复位；手工塞 `_applying:true` 模拟历史脏数据，reload 后确认被清理；卷头 ✎ 按钮存在，改名后卷名生效、`vol.updatedAt` 已写、存储串含新名、书级 `_updatedAt` 由 0 抬升；远端卷时间戳更新时 `changed:true` 且覆盖为新名，远端时间戳更旧（1000）和无时间戳两种都保持原名、`changed:false`；改名后分卷 ZIP 中央目录条目为 `1-远端新卷名.txt`、`2-第二卷.txt`；撤销/统计/进度三项无回归；4 个内联块 `node --check` 全通过。本版已上传至仓库（commit `46b7865`，2026-11-16）。
